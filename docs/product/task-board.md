# Task board

Each group has a Kanban board with four fixed buckets (columns) and custom buckets between them. Clients and admins create, edit and move task cards. Each task has its own chat, the same as the group chat. Tasks can be created from chat messages with the help of AI.

## Requirements

- Kanban board within a group, created with the group.
- **Four fixed buckets**, in this order, created automatically for every group, in this order at first. They cannot be renamed or deleted, but admins can reorder them like any other bucket:
  1. **To do**;
  2. **eGrant review** (eGrant checks the work);
  3. **<client> review** (the client checks the work; the name follows the group name);
  4. **Completed**. It shows its first 15 tasks in the column's order (the done circle puts a task on top, so these are the latest ones) and the total; "Show 15 more" loads the next 15, like the global board's "Show 50 more" (Phase 27, owner's choice). The pages loaded stay when the board reloads.
- **Custom buckets**: admins create, rename, delete and reorder them; a new one goes after the last bucket, where "Add column" sits. Deleting a custom bucket moves its tasks to To do.
- **Bucket order**: admins drag any bucket, fixed ones included, by its handle (mouse, touch or keyboard) to reorder the board. The order is stored per group and everyone looking at the board sees it change live. Clients cannot reorder buckets. "Add column" sits after the last bucket.
- **Drag & drop** of tasks between buckets and inside a bucket.
- **Done circle** on every card and in the task panel: checking it moves the task to the top of Completed, unchecking it moves it to the top of To do (it notifies like any move). Tasks in Completed show a checked circle and a struck-through title. Anyone who can move tasks can use it.
- **Clients and admins** create, edit and move tasks. Only admins manage buckets.
- **New task**: "Add task" in a column opens the full task form (every field) with that column chosen; nothing is saved until "Create", and closing discards the draft.
  - **Empty-link warning** (owner request, 2026-10-16): the first "Create" with the link field empty does not save. It shows "The link is empty. Adding one helps support resolve the task faster. Click Create again to save without it." under the link field (inline, not a dialog) and moves the focus there. A second "Create" saves without a link. The warning shows once per form: typing a link hides it for good. Editing an existing task never warns. Cards created in the AI review ("Turn into tasks") have the link field but no warning: that is a bulk review of proposals, not a task filled by hand.
- Realtime: changes by other users are visible immediately.
- **Task card:**
  - title;
  - description: the description editor (Phase 33 part P5): chat formatting, the AI button, the microphone and "Attach from the knowledge base"; attached items show as cards under it for everyone who reads the board (see [projects.md](projects.md#description-editor-part-p5));
  - linked knowledge (2026-10-18, owner request): on the board card (group board and global board) a small book icon with the number of attached knowledge items appears when there are any; hovering it, or the card's accessible name, says "3 knowledge items". The card carries only the count (`knowledgeCount` in the task DTO, one correlated subquery per card of the page, no extra query); the titles are in the task panel, where each attached item is a card that opens the item. The count and the panel's cards follow the same rule: only items everyone who reads the task may open (the group's, public, every folder up the tree public). An item that became admins-only or moved away is not counted and shows as "Item unavailable" in the panel until removed;
  - creator (who created it);
  - assignees (one or more people: clients of the group or its managers; an admin also assigns any other active admin, the superadmin included, who does not manage the client (owner request 2026-10-18); a client cannot choose an admin who is not a manager). Existing assignments are kept when a task is edited, even if the person has since stopped being a manager; only newly added assignees are checked (400 `invalid_assignee`; a disabled admin, a client of another group or a ziadatel is never assignable);
    - Picker for an admin (2026-10-18, the task form, the task panel and the AI review cards, which share `TaskForm`): the group's clients and managers first, then the heading "Other admins" (SK "Ostatní admini") with every other active admin, each row marked with a muted "not a manager" (part of the option's accessible name); a chosen one keeps that mark on its chip. The list is the same `GET /api/groups/:id/people` the form already loads (every active admin with `isManager`), so nothing new is fetched. An admin assigned this way reads the task like every admin, gets the usual `task.assigned`, move, deadline and urgent notifications of an assignee (by their modes and channels, as for any assignee), and the task is on their admin home's My tasks card (every client) and on the global board when the client filter includes that client ("Show all" from My tasks uses every client; the default "clients I manage" scope is unchanged, on purpose). The AI split still suggests only clients and managers.
    - Picker for a client (Phase 18): the list offers only the group's clients and its eGrant managers. An existing assignee who is an admin but not a manager keeps their chip with a muted "not a manager" and can be removed, but is not offered again. An admin who does not manage the group and finds no one to pick sees "Only clients and the client's managers can be assigned." A save refused with `invalid_assignee` shows "Someone you chose can't be assigned here any more." and refetches the group's people. See [client-managers.md](client-managers.md).
  - deadline (date);
  - **link**: an optional web address (http or https only, at most 2048 characters, trimmed; empty means none) pointing to where the issue is, so support can find it. In the panel a saved link shows as "Open link" under the field (new tab); the field stays editable and clearing it removes the link. A card with a link shows a small link icon. A value that is not an http(s) address is refused ("Enter a full web address starting with http:// or https://."; server 400 `invalid_url`);
  - **urgent** flag;
  - attachments (files, images);
  - link to the source message in chat (if the task was created from chat): opens the chat at that message, in the group chat or in the task chat it was written in;
  - **task chat**: the same chat as the group chat (threads, @mentions of anyone in the group and admins, @all, attachments, "Turn into tasks" and the "Turned into tasks:" links under a message).
- **Task panel tabs** (as built, Phase 9): under the task title the panel has two tabs, **Details** (the form) and **Chat (N)** (the task chat). The open tab is part of the address (`?tab=chat`), so a link can open a task straight on its chat at a message. Switching tabs keeps unsaved changes in the form, and closing the panel still asks about them. Opening the Chat tab marks the task's chat read. On phones the panel is a full-screen sheet and the chat fills it, with the message box at the bottom. A new task has no Chat tab until it is created.
- **Unread tasks** (as built, Phase 9): a new message in a task chat marks the task unread for everyone else; a reply in a thread you are in does too. An unread task's card shows its title in bold and a dot on the chat icon next to the message count. The group's **Tasks tab** shows one black pill, live (2026-10-17): the number of the group's tasks with a change you have not seen yet (the [unseen changes](../superpowers/specs/2026-10-17-unseen-changes-design.md) of the board, which include new messages in task chats that notify you), for clients too; screen readers hear "3 tasks with a new change". The plain total of your open assigned tasks is not shown there. It reads `GET /api/groups/:id/board/unseen` (the same ids that mark the cards) and refetches 2 s after a task or task chat event of the group, on `seen:changed` and after a reconnect. Opening the task's Chat tab reads the whole chat and clears it (on every device). Your own messages never make a task unread for you.
- **Notifications** (delivered from Phase 6):
  - when a task moves to another bucket, its creator and its assignees are notified (not the person who moved it);
  - every assignee is reminded 3, 2 and 1 days before the deadline, at 09:00 (Europe/Bratislava), while the task is not in Completed. The job `tasks.deadline-reminders` runs daily and records a `task.deadline` event per assignee, at most one per task and day, counted in Bratislava days (so daylight saving changes do not shift it);
  - an **urgent** task reminds its assignees every 3 hours between 08:00 and 20:00 (Europe/Bratislava) until it is in Completed or no longer urgent. The job `tasks.urgent-reminders` runs at 08, 11, 14, 17 and 20 and records a `task.urgent` event per assignee, at most one per task and Bratislava hour slot. A task without assignees reminds nobody;
  - task chat messages notify like the group chat.
- **Custom reminders** (Phase 19, see `reminders.md`): anyone working on a task can set their own reminder times on it, for themselves and the people they add; others can subscribe ("Remind me"). They sit beside the automatic deadline and urgent reminders above, which stay as they are and cannot be turned off: those are a safety net for every task with a deadline or the urgent flag, for its assignees, on a fixed rhythm; custom ones are a moment someone chose, for anyone who asks. A task in Completed sends neither. The task's "Add to calendar" exports the deadline (all-day) and the upcoming custom reminders in one `.ics` file; the automatic reminders are not exported.
- **Source lines** in the task panel: "Ticket: #123 subject" for a task made from a ticket (Phase 21), "Meeting: <title>" for a task made from a meeting's action items (2026-10-17, see `knowledge-base.md`, "Meetings"; shown only to people who can read the meeting, opens it in the Knowledge tab).
- **Solve with Claude** (Phase 29, see `solve-with-claude.md`): admins open a task in Claude from the task panel header, with its fields, description, chat, file names, the client's eGrant instance and optional notes.
- **Time on done** (Phase 32, part A2; full rules in `finance.md`, "Time on done"): when an admin assignee completes a task (the done circle, a drag into Completed, the panel's bucket select, on the group board or the global board, or creating it in Completed) the board answer says `askTime` and the time dialog opens over the board, which does not wait for it; the other admin assignees are asked by a notification and a dashboard row. The panel's Details tab shows **My time** under the assignees for an admin assignee (and everyone's time in one line for a finance admin). A client never sees any of it.
- **Creating tasks from a chat message** (with AI): see `ai-task-split.md`. The approved cards go to the top of To do, in the order shown in the review, all at once or none; each keeps a link to its message, and a message file kept on a card is copied, so the card and the message each have their own file. The source's web addresses, mentions and shareable knowledge items reach the cards too (see `ai-task-split.md`, "Nothing of the source is lost").
- **Project and event** (Phase 33 part P2, see [projects](projects.md#links-and-filters-part-p2)): under the deadline the task form has a **Project** select ("No project", the client's active projects) and, once a project is chosen, an **Event** select ("No event", its events, coming ones first). A card shows a small chip with the project's colour dot and name (", event" when set). The board has its first **filter row**: Project and Event menu pills, in the URL (`?project=&event=`) and remembered per client; on phones one "Filters (n)" pill opens them.

## Global task board (as built, Phase 20)

Admins have a board across clients at `/tasks` (header link "Tasks"):

- Columns by step: **To do**, then one column per custom bucket name of the chosen clients (buckets with the same name in different clients share a column, compared without case and diacritics; at most 12, the rest folded into **Other steps**, whose cards name their bucket; see `admin-home.md`, Custom bucket columns), **eGrant review**, **Client review** and, with "Show completed", **Completed** (the last 30 days). Each column shows its total and its first 50 cards; "Show 50 more" loads the next ones. Cards are sorted urgent first, then by deadline (none last), then by client name.
- Each card is the group board's card with a line on top: the client's logo and name. It has no done circle and cannot be dragged: a card opens the task panel over the board (`/tasks?…&task=<id>`), whose bucket select moves the task; closing the panel returns to the same filtered board. There is no "+ Add task": a task is created on its client's board.
- Filters, all in the address so a view can be bookmarked: clients (the knowledge list's client filter; by default the clients I manage, or all when I manage none; choosing every client is `clients=all`, which the dashboard's "Show all" uses too; the last filters, all but the title search, come back on the next visit; see non-functional.md, "Lists remember their filters"), assignee (me, anyone, unassigned, or a person among the assignees of the chosen clients), urgent, "Only where I take part" (`mine=1`: tasks I created or am an assignee of; it narrows the assignee filter, so with a person chosen it shows that person's tasks I created or share), deadline (overdue, next 7 days, no deadline; by Bratislava's date), a title search (from 2 characters) and "Show completed". "Clear filters" appears when anything differs from the defaults. On phones the filters collapse into one "Filters (n)" pill that opens a sheet. A filter the server refuses (an old bookmark) resets the board to its defaults.
- The board follows task changes in any client live (refetched about 2 seconds after the last change while the page is visible); since 2026-10-17 chat activity and opening a task (`seen:changed`) refetch it too, for the unseen marks.
- **Unseen changes** (2026-10-17, [spec](../superpowers/specs/2026-10-17-unseen-changes-design.md)): a card of a task with a change I have not seen (a notification about it after I last opened its panel) shows a bold title and a yellow marker in its top right corner (2026-10-18): a yellow ring with a dot inside when the changes include a message in its chat ("Nová správa"), else a plain yellow dot ("Nová zmena"), on the global board and on the group board (`GET /api/groups/:id/board/unseen`, `{ taskIds, messageTaskIds }`, refetched on the group's task and task chat events and on `seen:changed`). The marker is its own button beside the card's link: hover, focus, a tap or a long press shows what changed since I last opened the task ("Priradené vám", "Presunuté: Na spracovanie → Hotové", "Termín zajtra", "1 nová správa (Jana)"; at most 5 lines and "a N ďalších"), fetched then from `GET /api/tasks/:id/unseen-summary`. Opening the panel (either tab) first fetches the same summary, shows it in a small yellow banner at the top of the panel (until dismissed or closed) and then marks the task seen. A refetch (a task changed, or the page got the focus back) keeps the extra pages loaded with "Show 50 more" and reloads them to the same depth (Phase 27 W5); only a change of the filters goes back to the first page of each column.
