# Group chat

Each group has one chat (at the start) with realtime messages, threads like Slack, @mentions and attachments. Messages can be turned into tasks with AI. The same chat is used inside every task. Users can edit and delete their own messages, see unread indicators, and missed messages are loaded after a reconnect.

## Requirements

- **One chat per group** (at the start).
- Messages in real time (WebSocket).
- After a lost connection, missed messages are caught up (loaded) after reconnect.
- **Threads:** under each message a reply thread can be opened (like Slack). Inside a thread every message has "Reply": no nested thread, the reply shows a quote of the message it answers.
- **Formatting:** bold, italic, strikethrough, lists, links, quotes, code, headings.
  - Composer (Phase 28, `apps/web/src/features/chat/editor/`, [ADR 0025](../decisions/0025-prosemirror-chat-editor.md)): the field of every chat (group, thread, ticket and task chat, and the edit box) is a WYSIWYG editor that shows the formatting while typing. Markdown typed in it turns into formatting at once (`**bold**`, `_italic_`, `~~strike~~`, `` `code` ``, `[text](url)`; at a line start `- ` or `* `, `1. `, `> `, `#`/`##`/`###` and ```` ``` ````); Backspace right after a shortcut brings the characters back, and at the start of a list item, heading or code block it turns the line back to plain text. Pasted Markdown renders; pasted formatted text (a web page, a document) keeps the formatting the chat supports; copying out gives Markdown. The toolbar buttons show which formats are on at the caret; Link asks for the address in a row inside the box ("egrant.sk/x" becomes `https://egrant.sk/x`; only http, https and mailto). Mentions are pills (one character for Backspace); as before, a typed `@all` (the label of the language) and a typed `@Name` of someone already picked in the draft are sent as mentions too, at word edges and never inside code (`toStored` in `composer-text.ts`, run on send and for the counter). Enter rules as before: on a computer Enter sends and Shift+Enter makes a new line (the next list item; an empty item, an empty last line of a quote or code block leaves it); on a touch screen Enter is that new line and Send sends. On phones (under 641px) Send is a paper-plane icon button named "Send" ("Odoslať"), so the row of plus, voice and AI buttons keeps room for the formatting marks ([design](../design/tokens.md)). One **plus** button ("Pridať", `aria-label` "Add"; not in the edit box) replaces the separate paperclip and knowledge buttons: it opens a menu (Radix `DropdownMenu`, arrow keys, 44px items on phones) with Znalosti, Úlohy, Tiket, each opening the attachment picker directly on that tab, and "Nahrať súbor zo zariadenia", which opens the native file chooser; every item has a 16 px outline icon before its label (book, circle-check, ticket, paperclip from `features/chat/icons.tsx`, decorative, so the accessible names stay), and the attachment picker's three tabs carry the same icons (drag-and-drop and paste still work). A reader who gets knowledge only through messages (a žiadateľ in a ticket chat) has no picker, so the button goes straight to the file chooser (owner request 2026-10-18). An **emoji** button (a smiling face, "Vložiť emoji"; in the edit box too) opens the reactions' emoji set in the same sheet (`emoji-picker-sheet.tsx`, the same lazy chunk); a pick is typed at the caret and closes the sheet (owner request 2026-10-18). The draft is stored as the same Markdown, one line per line, so rendering, search, notifications and digests are unchanged; the counter counts the stored Markdown. The editor is a lazy chunk; until it loads the box shows the placeholder.
  - As built (`apps/web/src/features/chat/format/`): `**bold**`, `_italic_` (only at a word edge; an underscore inside a word never counts, so `snake_case` and `__init__` stay text), `~~strike~~`, `` `code` ``, fenced ```` ``` ```` blocks (an unclosed fence runs to the end; a one-word first line such as `js` is a language tag and is not shown), `> ` quotes (up to 3 levels), `- ` and `N. ` lists (a list keeps its first number), `# `, `## ` and `### ` headings (Phase 28; a line of its own, shown as `h3`–`h5` so they stay under the page's headings), bare URLs (trailing `.,;:!?*~` and an unmatched `)` are not part of the URL; an invalid one or one over 2048 characters stays text) and `[text](url)` (text without `` ` `` or `[`). Links work only for `http`, `https` and `mailto` and open in a new tab with `rel="noreferrer noopener"` and show their real address as a tooltip (`title`); anything else, like `javascript:`, stays text. HTML in a message is shown as text. Mentions show as pills with the person's name (`@unknown` when the person is no longer known). The parser is linear-time on hostile input and takes its mention tokens from the shared `splitMentionTokens`, so pills match the people the server notifies (shared cases in `packages/shared/src/chat-mention-cases.ts`).
- **Mentions (@tags)** of users: clients of the group and its eGrant managers; @all reaches the group's clients and managers. Admins who do not manage the group still read the chat and get message and thread notifications, but cannot be mentioned and are not reached by @all.
  - Picker (Phase 18): the `@` list offers only the group's clients and its eGrant managers (`isPickable`), and its "Everyone in this group" row carries the hint "The group's clients and its eGrant managers". A send refused with `invalid_mention` keeps its failed row with "Someone you mentioned can't be mentioned here any more." (Retry stays); an edit refused the same way keeps the text and shows that line. Both refetch the group's people. See [client-managers.md](client-managers.md).
- **Saved replies (F7, 2026-10-18; canned replies):** an admin types `/` at the start of the text or after a space (never inside a word or a URL) in any composer (group chat, task chat, ticket chat, a thread or the edit box) and gets a list of their own saved replies and the team's shared ones, matching what follows the `/` by title first, then by text (case- and diacritics-insensitive). Arrows, Enter/Tab and Escape work as in the `@` list; a pick replaces the `/query` with the reply's text (Markdown kept, one undo step). `{{name}}` becomes the name of the person answered: the author of the message being quoted, else a ticket chat's initiator; with neither it stays for the admin to fill in. A bare `/` with no saved replies at all says where to add them; otherwise nothing shows when nothing matches. Clients never get the list. Saved replies are managed on `/settings` (see `profile.md`). The list is a lazy chunk with its `snippets` texts, loaded on the first `/`.
- **Attachments:** files and images, with image previews. Every file attached in any chat (group, task or ticket chat) also appears in the group's knowledge base as a read-only "From chat" item that opens the chat at the message, and goes when the message is deleted (Phase 25, see [knowledge-base](knowledge-base.md)). Its author or an admin may save it as a normal file item, which gets its own copy of the file; the message keeps its attachment.
- Users can edit and delete their own messages.
- **Reactions** (Phase 28, [design](../superpowers/specs/2026-10-17-phase-28-reactions-and-attachments-design.md)): everyone who reads a chat (group, task or ticket chat, a žiadateľ in their ticket chat too) reacts to any live message with one emoji at a time: the quick row 👍 ❤️ 😂 😮 😢 🙏 ✅ or "More emoji" (about 200 common emoji in seven groups, flowers and plants among them, a lazy chunk, no new dependency; owner request 2026-10-18: a **Frequently used** group at the top lists the person's 16 most picked emoji, most used first, kept per browser in `localStorage` (`emoji-usage.ts`); every pick in the sheet counts, reactions and composer inserts alike, the quick row does not). Desktop: "Add reaction" is the first button of the hover toolbar; phones: the quick row sits at the top of the message's action sheet (long press or double tap). Under the message each emoji is a chip with its count; the reader's own are highlighted (`aria-pressed`) and a tap toggles them at once (optimistic until the server answers). Hovering, focusing or holding a chip lists who reacted. A person may add several different emoji; a message takes at most 20 different ones. Reactions arrive live (`chat:reactions`) and never notify anyone (no in-app event, push or email). A deleted message loses its reactions.
- **Knowledge items in a message** (Phase 28): in a group's chats (group chat, its task and ticket chats) a message can carry up to 5 items of that group's knowledge base, picked with the book button next to the file button (a search dialog listing only items everyone in the group can see, each with its type icon). A message may hold items only. Each shows as a card with the type icon, title and folder path; a card opens the item in the knowledge dialog. Items are checked again whenever the message is shown: one made admins-only, moved into an admins-only folder, moved to another client or deleted shows "Item unavailable". In a ticket chat a žiadateľ gets no picker but opens attached items read-only, only that item, through the message. Editing a message keeps its items; deleting it removes them. Phase 34 (P34-C): in a client group an admin's Knowledge tab has a source switch, **This client** (default) and **eGrant tím**, the second listing only the admin group's items marked "Shareable with clients"; such a card shows the **eGrant tím** badge and no folders, and the client opens it read-only through the message. In the admin group itself any item of any client can be attached. See [knowledge-base.md](knowledge-base.md#knowledge-of-the-admin-group-phase-34-part-p34-c).
- **Tasks and tickets in a message** (Phase 34, part P34-A): the button next to the file button now opens one picker (a dialog, a sheet on phones) with three tabs, **Knowledge · Tasks · Tickets** (the last tab is remembered per browser). Each tab has a search (tasks by title from 2 characters, open first and then completed; tickets by number `123` or `#123`, subject fragment or the start of the text, open ones unless "Include resolved" is on) and a checkbox list; the picked items of all three tabs are chips at the bottom and "Attach (n)" sends them. At most 5 knowledge items, 5 tasks and 5 tickets per message; a message may hold them only. Only this group's tasks and tickets can be attached (in the admin group the cross-client picker, see below). The message shows a card per item under the knowledge cards: a task card has the done mark, title, bucket, up to three assignees, deadline (red when overdue) and an urgent mark and opens the task panel; a ticket card has `#number`, subject, status and riešitelia and opens the ticket page. The cards show live values and are checked again on every display: a deleted task, or a ticket deleted or moved to another client, shows "Task unavailable" / "Ticket unavailable". Nobody is notified by an attachment. A žiadateľ has no picker; in their ticket chat attached tasks are removed from their copy of the message and only the tickets they can read (their own) stay, with no trace of the others. Editing keeps the items; deleting the message removes them.
- **The picker in the admin group** (Phase 34, part P34-D): in "eGrant tím" (its chat and its task chats, read by admins only) the three tabs list **every client's** knowledge, tasks and tickets. Each tab has the client filter at the top: "eGrant tím" first, then **Managed by you** (my clients, each with the small ink dot used on `/groups`), then the other clients, searchable; the default is **all clients**, "Only my clients" narrows to "eGrant tím" and mine, and the choice holds across the three tabs while the picker is open. The Tickets tab leaves "eGrant tím" out (it has no tickets) and has a **Without client** switch for tickets no client was found for. Every result row names its client with the logo (and the dot for my clients). Knowledge there also lists admins-only items, marked **Only eGrant**, and items in admins-only folders: only admins read this chat. On the message, a task or ticket card of another group names its client the same way (a ticket without one: "Without client"), and a task card opens the task in its own group. The same items are refused in a client group's chat. In the description editor of an admin-group task, project or event the knowledge picker stays the group's own (P34-C may widen it).
- Unread indicator. As built (polish C1): a message counts as unread on the Chat tab and in the groups list when it is newer than the user's read mark and it is a top-level message, a reply in a thread the user started or replied in, or a reply that quotes the user's message. Naming someone in a reply (Phase 20) makes them one of the thread's people too: that reply and the later ones count as unread for them and the thread gets its dot; their older unread replies stay unread (the mention never moves an existing read mark). @all in a reply adds nobody to the thread, so a whole group never follows it. The user's own messages never count. Reading the main feed does not read the threads: a thread with unread replies shows a purple dot before its "N replies" link until the user opens it; opening it marks those replies read and the badge drops by that number at once (also on the user's other devices).
- Opening a chat. A chat read before opens at its first unread message, with the "New messages" line just under the top edge; with nothing unread, or in a chat never read, it opens at the newest message. A link to a message opens at that message instead.
- Message actions: **"Reply in thread"** (inside a thread: **"Quote"**), **"Turn into tasks"** (AI, see `ai-task-split.md`; as built it sits behind "More" on desktop and in the phone sheet, only when the server has the AI on and only on messages with text, and opens the review dialog), and Edit and Delete on your own messages. Every action has a 16 px outline icon (reply arrow, thread, copy, translate, sparkle for the AI action, pencil, trash), on the hover toolbar, in the "More" menu (icon before the label) and in the phone sheet. On a computer they show on hover, above the message. On a phone or tablet there is no "⋯" button: a long press or a double tap on the message opens them as a list at the bottom of the screen, with an extra **"Copy text"** (a long press does not select text there); links, mentions, files and images still open on a single tap. Screen readers and keyboards reach a hidden "Message actions" button on each message. Group, ticket and task chats all work this way. A message turned into tasks shows a footer line "Turned into tasks:" with a link to each task (`message-tasks.tsx`); a completed task is struck through and muted. It updates live from the `chat:message_tasks` event (also for replies in an open thread).
- The same chat component is used for the task chat (see `task-board.md`; its plain messages notify only the task's people, owner 2026-10-18). As built (Phase 9): every task has its own chat, created the first time someone opens it, and deleted with the task. In the task panel a thread opens over the chat (there is no room beside it). Opening a task's Chat tab marks that whole chat read, its threads included, so the purple thread dots of that chat go away at once, also on the user's other devices. A task chat has the same "Turn into tasks" action and "Turned into tasks:" footer as the group chat (both use `useMessageTaskTools`).
- The same chat component is the **ticket chat** (Phase 21, part 21.3): every ticket with a client has one, created when the ticket gets its client and moved with the ticket (its messages' files move too). Whoever reads the ticket reads and writes its chat: admins, the group's clients and the ticket's ziadatel initiator, whose sockets get its messages in their own room. The initiator can be mentioned there; `@all` means the ticket's followers. Its messages, replies included, notify the ticket's followers as ticket events (part 21.6), and a mention there notifies the named reader as a ticket board event; both open the ticket, never a group chat (see [notifications](notifications.md)). Its people for mentions and names come from `GET /api/channels/:id/people` (the group's clients and managers plus the initiator), since a ziadatel cannot read the group's people, and its files are uploaded through the ticket (`POST /api/tickets/:id/files`), so the initiator can attach files too (part 21.4). It sits on the ticket page (see `tickets.md`), its threads open over the list.
- **AI text tools and voice input** (Phase 28, [design](../superpowers/specs/2026-10-17-phase-28-ai-text-tools-and-voice-design.md)), in the composer of every chat (group, task and ticket chat; a new message and a thread reply, not when editing), next to Send:
  - The **AI button** (sparkle) opens a menu: *Fix mistakes* (only commas, full stops, diacritics and typos), *Make it formal* (a professional tone that is still a chat message, not an email; spoken enumerations become a numbered list, run-on dictation becomes sentences and paragraphs) and, only in groups whose eGrant link is not on a `.sk` domain, *Translate* to English and to the client's language (the instance's country domain, e.g. `.cz` → Czech; else the most common profile language of the group's clients other than Slovak and English; else only English). The answer replaces the draft; *Undo* next to the button brings the old text back while the draft is unchanged. Nothing is sent. Admins and the group's clients get it; a ziadatel does not. A failure or the rate limit shows a short message and keeps the draft.
  - The **microphone** records until the person taps *Stop* (no cut-off on silence; it stops by itself at 5 minutes), with a red dot, a timer (`0:42 / 5:00`) and *Cancel*. The server transcribes the audio (the meetings' `TRANSCRIPTION_PROVIDER`) and the text is added to the end of the draft for review, never sent; the audio is not stored. Everyone who reads the chat gets it, a ziadatel included.
  - Both buttons show only when the server offers them for that chat (`GET /api/channels/:id/ai-tools`, read once per chat). Code: `apps/web/src/features/chat/ai-tools/` and `voice-input/` (self-contained: the composer passes the channel and `getText` / `setText`, which read and replace the editor's draft as Markdown; an AI answer is one undo step in the editor, so Cmd/Ctrl+Z also brings the draft back, and its Markdown, such as a numbered list, shows formatted).
- **Translate a received message** (2026-10-19, [ADR 0061](../decisions/0061-translate-received-messages-stored-per-language.md)): in every client group (never the admin group; until 2026-10-21 only where the eGrant link is not on `.sk`, [ADR 0063](../decisions/0063-translate-received-messages-in-every-client-group.md)), every reader of a group, thread, task or ticket chat, a žiadateľ too, gets **Translate** on messages someone else wrote (the hover toolbar on a computer, the long-press list on a phone; never on their own or a deleted message, nor on one with only attachments). The server translates it into the language the reader sees (else their profile language) and the translation replaces the text in place, with a line under it: "Translated from <language>" and **Show original** (then **Show translation**). A text already in the reader's language stays as it is, marked "Already in <language>". While it runs the line says "Translating…"; a failure or the rate limit says so with **Try again**. Mentions, links and formatting are kept. Each message is translated once per language and version: the next reader with that language gets the stored translation at once, and an edit or delete drops it (`POST /api/messages/:id/translate`; offered when `GET /api/channels/:id/ai-tools` says `translateIncoming`). Code: `apps/web/src/features/chat/translate/`.
- **Outside the chat** (Phase 33 part P5): the same AI button, microphone and knowledge picker sit in every long description field (task, ticket text, project, event, knowledge body, meeting summary, finance item), on the chat's editor in document mode (Enter makes a new line). They call the group's routes and share each person's limits with the chat. Plain-text fields (meeting decisions and questions, notes for Claude) and the bulk email text block get the AI button and the microphone too (admin routes where no group applies). See [projects.md](projects.md#description-editor-part-p5).
- **Links to a message** carry the message and its chat: `?message=<id>&c=<chatId>`. A group chat message opens the group's Chat tab at it (`/groups/<group>/chat?message=…&c=…`); a task chat message opens the board with that task's panel on its Chat tab (`/groups/<group>/tasks/<task>?tab=chat&message=…&c=…`); a ticket chat message opens the ticket page (`/tickets/<ticket>?message=…&c=…`, Phase 21; also from the admin home's unread mentions). Either way the message is scrolled into view and highlighted for 2 seconds. "Created from a message" on a task uses the same links, so a task made from a group chat message or from another task's chat message both lead back to it.
- Message search within a group (see `profile.md`, phase 16).

## Phase

Phase 5 (realtime, catch-up, edit/delete own, unread, threads, mentions, attachments with previews). Phase 9 (task chat, "Turn into tasks"). Phase 6 (notifications). Phase 21 (ticket chat). Phase 28 (AI text tools and voice input, reactions, knowledge items in messages).
