# 0013 Web Push with VAPID

Date: 2026-10-16
Status: accepted

## Context
Phase 6 sends notifications to the browser when the app is closed. Spolu is self-hosted only ([ADR 0008](0008-self-hosted-only.md)), so a push path must not depend on a vendor account. The service worker is generated by Workbox ([ADR 0011](0011-pwa-with-vite-plugin-pwa.md)).

## Decision
- Web Push with VAPID through the `web-push` package (pinned, with `@types/web-push`). No Firebase and no third-party push service: each browser's own push endpoint is called directly. The keys come from `pnpm --filter @spolu/server vapid:generate`, once per environment, in `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT`. With none set, push is off (`deps.push` is null) and the web hides the toggle.
- The push and notification-click handlers live in the static file `public/push-sw.js`, which the Workbox service worker loads with `importScripts`. The caching setup of ADR 0011 does not change.
- Senders sit behind a `PushSender` interface, like email. `PUSH_PROVIDER=fake` selects a fake that records sends (and appends JSON lines to `PUSH_FAKE_FILE`); it is for tests and e2e, never for a deployed environment.

## Consequences
- A 404 or 410 from the push endpoint means the subscription is gone and is deleted; any other failure is retried by the job queue.
- Losing the private key invalidates all subscriptions; users subscribe again.
