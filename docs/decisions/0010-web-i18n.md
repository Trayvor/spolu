# 0010 Web i18n with i18next

Date: 2026-10-15
Status: accepted

## Context
The UI is translated (SK, EN). We need key lookup, language switching at runtime and React bindings.

## Decision
- `i18next` and `react-i18next`. Both locale files (`src/locales/{en,sk}.json`) are bundled statically; they are small.
- No language-detector plugin and no HTTP backend: `detectInitialLanguage` is a few lines of our own code (stored choice, then browser language, default `en`).
- Cost: about 17 kB gzip of initial JS (entry 103 to 114 kB plus a 5.6 kB shared chunk) (measured at build, see `docs/architecture/performance.md` for the budget).

## Consequences
- Adding a language means one JSON file plus an entry in `LANGUAGES`; a test enforces identical keys.
- If locale files grow large, split them per feature and load them lazily.
