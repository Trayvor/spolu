# MCP server: connect an AI assistant

Help by eGrant speaks the [Model Context Protocol](https://modelcontextprotocol.io) at `https://help.egrant.sk/mcp`, so Claude (Claude Code, Claude Desktop) or any MCP client can read and change Help **as you**: it sees and changes exactly what you may in the app, nothing more. Design: [spec](../superpowers/specs/2026-10-18-mcp-server-design.md), [ADR 0033](../decisions/0033-mcp-server-over-the-http-api.md); OAuth: [spec](../superpowers/specs/2026-10-18-mcp-oauth-design.md), [ADR 0034](../decisions/0034-mcp-oauth-authorization-server.md).

Admins only. Two ways in:

- **claude.ai and Claude Desktop: a custom connector with just the address** (OAuth, no token to copy). See [Connect Claude with the URL](#connect-claude-with-the-url).
- **Claude Code, scripts, any MCP client: a personal token.** See [1. Make a token](#1-make-a-token).

## Connect Claude with the URL

1. In claude.ai (or Claude Desktop, which shares the same connectors) open **Settings → Connectors → Add custom connector**.
2. Name it, for example "Help", and enter the URL **`https://help.egrant.sk/mcp`**. Leave the advanced OAuth fields (client ID, secret) empty: Claude registers itself.
3. Press **Connect**. Claude opens Help's consent page. Sign in with your email code if you are not signed in; the page shows who asks (Claude), where you return (`claude.ai`) and the access: **Read only** or **Read and change** (as for tokens below).
4. Press **Allow access**. You return to Claude, and the connector is listed as connected. Help emails you that an assistant was connected.

Claude keeps itself signed in (a one-hour access token, refreshed automatically for 30 days from the last use). **Settings → AI access (MCP) → Connected assistants** lists each connection with its access, host and last use; **Disconnect** ends it at once. Deactivating an admin disconnects everything. At most 10 connections per person.

Claude Code can use the same URL (`claude mcp add --transport http help https://help.egrant.sk/mcp`, then `/mcp` → authenticate) or a token as below.

Only Claude's own addresses (`https://claude.ai`, `https://claude.com`) and your own computer (`http://localhost`, `127.0.0.1`, `[::1]`) may receive an approval; other OAuth clients are refused at registration (ADR 0034). For developers: discovery starts at the `401` of `/mcp`, whose `WWW-Authenticate` names `/.well-known/oauth-protected-resource/mcp`; the authorization server metadata is at `/.well-known/oauth-authorization-server` (registration `/oauth/register`, authorization `/oauth/authorize`, tokens `/oauth/token` with PKCE S256 and `resource=https://help.egrant.sk/mcp`, revocation `/oauth/revoke`; scopes `read`, `write`).

## 1. Make a token

Admins only. Open **Settings → AI access (MCP)**, name the token (for example "Claude on my laptop"), choose the access and how long it is valid, and press **Create token**.

- **Read only**: the assistant reads groups, chats, tasks, tickets, knowledge, projects, reminders, weekly summaries, the audit log, your settings, bulk email and, if you hold the finance right, finance. It may also use the app's AI helpers that change nothing (translating, drafting a ticket reply, proposing tasks) and count a bulk email audience.
- **Read and change**: it can also create and edit tasks (also from a ticket or a message), board columns, reminders, tickets (moving them to another client, their project, watching a client's tickets), chat messages (editing your own, reactions), knowledge items, projects and events, Teams meetings (which send Outlook invitations), bulk email drafts and a test to yourself (never the send to recipients), your notification settings, canned replies, saved views and substitutions, and finance items (a client's, and the organisation's: contracts of several clients with their shares, expenses), the admins' salaries and the documents linked to salaries and expenses, folders, time and rates (finance holders). **No tool deletes anything.**
- Valid for 7, 30, 90 days or 1 year. At most 10 active tokens per person.

The token (`spolu_mcp_…`) is shown **once**: copy it then. Treat it like a password; anyone with it acts as you. Revoke it on the same card when a laptop is lost or the assistant is no longer needed; deactivating an admin revokes all their tokens. Every new token also sends you an email (its name and when it was made; never the token): if you did not make it, revoke it in Settings at once.

## 2. Connect

### Claude Code

The card shows the command with your token filled in:

```bash
claude mcp add --transport http help https://help.egrant.sk/mcp \
  --header "Authorization: Bearer spolu_mcp_…"
```

Then `/mcp` in Claude Code lists the server as connected.

The copied command contains the token, so it lands in your shell history and, once added, in `~/.claude.json`: keep both private, or clear the history line.

### Claude Desktop

Prefer the custom connector with the URL ([above](#connect-claude-with-the-url)). With a token instead, use the `mcp-remote` bridge (needs Node.js) in `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "help": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote@0.14.3",
        "https://help.egrant.sk/mcp",
        "--header",
        "Authorization:${HELP_TOKEN}"
      ],
      "env": { "HELP_TOKEN": "Bearer spolu_mcp_…" }
    }
  }
}
```

### Any other client

Streamable HTTP, stateless: `POST /mcp` with `Authorization: Bearer <token>` and one JSON-RPC message in the body (a batch array only in protocol `2025-03-26`, which is also assumed without an `MCP-Protocol-Version` header: at most 10 messages; `2025-06-18` and later removed batching, so with their header an array answers `400`, JSON-RPC `-32600`); answers are `application/json` (no SSE stream, no session id; `GET` and `DELETE` answer `405`). Protocol versions `2025-11-25`, `2025-06-18`, `2025-03-26`. A browser page cannot call it from another origin (`Origin` other than Help's: `403`).

The assistant cannot reach your own settings routes that hold secrets: the MCP tokens and connections, passkeys and the calendar subscription (`/api/me/calendar-feed*`, [calendar-feed.md](../product/calendar-feed.md)) are not in the allowlist, so it can neither read nor reveal your calendar link.

`get_ticket` (2026-10-19) also returns `rating` (the token user's own rating, whether they may rate now and until when) and, to an admin's token, `ratings` (every rating with the rater and comment; `null` for anyone else). The admins' ratings reads are tools (`get_ticket_ratings_summary`, `list_ticket_ratings`, 2026-10-21); rating itself is not: `PUT /api/tickets/:id/rating` is not on the allow-list, so an AI assistant never rates on someone's behalf.

Not tools either, by rule: deletes, uploads, the auth, session and MCP token routes, the finance grant, the calendar feed, "Mark all as read" and the snooze of the notification centre, sending or cancelling bulk email, and ending a substitution (a `DELETE`). A few `POST` routes that change nothing (the AI helpers, the bulk audience count and list) are marked `read` in the allowlist, so read-only tokens reach them; every other non-`GET` needs a write token.

A change made through MCP is the app's own request: everyone sees it live and is notified as if you had done it in the app. An edit tool takes an optional `updatedAt`; without it the current version is changed.

## 4. Limits and audit

- Per person (all your tokens together): 120 requests and 30 changes a minute; each message of a batch counts. The app's own limits per person apply on top. After 30 failed sign-ins a minute from one address, every request from it answers `429` for the rest of that minute.
- A tool answer longer than 100 000 characters is cut, with a note to narrow the query. The whole answer to one POST is at most 5 MB: in a batch, the request whose answer crosses it ran but answers a JSON-RPC error (`-32603`, "Answer too large"), and the ones after it are not run.
- Every change (also a refused one) is logged: who, which tool, on what, when and how it ended, never the content. You see your last 50 on the settings card. Entries older than 180 days are deleted daily (job `mcp.cleanup-audit`, 03:20).
- Every change a tool makes to a shared record also appears in the admins' audit log „História zmien“ ([product/audit-log.md](../product/audit-log.md)) as „<your name> cez AI“ with the token's (or the connection's) name. Making and revoking a token and approving and revoking a connection are recorded there too (name, scope, expiry; never the token).

## 5. Errors

- HTTP `401`: no, wrong, expired or revoked token (or connection), or your account is deactivated; the answer's `WWW-Authenticate` names the OAuth metadata. `403`: the account is not an admin, or a foreign `Origin`. `429`: too many requests.
- A tool answer with `isError: true` carries the app's `{ status, error }`: `404 not_found` (unknown, or not yours to see), `403 forbidden` (not allowed, or a read-only token: `detail: "read-only token"`), `400 validation_failed` with `issues`, `409 …_changed` (someone edited it meanwhile).
