# Audit log ("História zmien") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One general audit log for admins: who changed what and when, across groups, memberships, managers, admins, the finance right, tasks, buckets, tickets, knowledge, projects and events, finance items, folders, time and rates, MCP tokens and OAuth connections, passkeys, bulk email sends and the eGrant webhooks. Filterable by entity type, one record, client, author and date; keyset-paginated; finance rows only for finance holders.

**Architecture:**
- A new server module `modules/audit/` owns one append-only table `audit_log` (no foreign keys, snapshot labels, field-level diffs from an allowlist). Other modules call its exported `recordAudit(tx, by, entries)` **inside the transaction of the change**, with the author passed explicitly as `by: AuditActor` (built by `auditActorOf(request)`, `egrantActor(…)` or `systemActor(…)`).
- MCP calls are recognised through `runAsUser`'s new `via` (token id and name), so a change made through the AI records the person and the token.
- One read route `GET /api/audit` (`requireAdmin`, `canReadAudit`, finance rows filtered in SQL by `auditCategoriesFor`), keyset-paged by `(created_at, id)`, with one `in (…)` query each for current names, groups, causes and live-record existence (through registered per-module resolvers).
- A daily pg-boss job `audit.cleanup` deletes rows older than 730 days in batches.
- Web: a lazy `/audit` route with the lazy `audit` namespace (nine locales), entry links on the Admins page and "História" items in the detail menus.

**Tech Stack:** Fastify 5, Drizzle + drizzle-kit, PostgreSQL 17, pg-boss, React 19, TanStack Router and Query, i18next lazy namespaces, Vitest, Playwright. No new dependencies.

**Spec:** [2026-10-19-audit-log-design.md](../specs/2026-10-19-audit-log-design.md). Read §3 (what is recorded), §5 (table and indexes), §7 (permissions) and §13 (open questions; this plan follows the recommended answers) first.

## Review Focus

- **A change committed without its row, or a row without its change.** The insert must be on the same `tx` as the change; a `recordAudit(db, …)` call outside the transaction compiles (both are `Db`) but breaks atomicity. Test in Task 2: `recordAudit inside a rolled-back transaction leaves no row`; every module task has `<fn> writes no row when the change fails` (a forced `TaskChangedError` / `FinanceChangedError`).
- **Finance rows leaking to a non-finance admin.** Through the entity filter, the type filter, a cursor taken by a finance admin, the `cause` of a general row (a deactivation's consequence is a `finance_access` row: the general row's `cause`/consequence link must not reveal it), or `changes` of a general row. Tests in Task 4 (`audit/leaks.test.ts`) and Task 7 (`deactivating a finance admin: the non-finance viewer sees the deactivation, not the revoked right`).
- **Content in `changes`.** A description, body or note must appear as `{ changed: true }` only. Test in Task 2 (`diffFields stores text fields as changed only`) and per module (`the description's text is not in the row`: assert `JSON.stringify(row.changes)` does not contain the test's unique description string).
- **The wrong author through MCP and webhooks.** An MCP write must record `actor_kind = 'mcp'` with the token; an eGrant webhook must record `egrant` with the instance origin, never a person. Tests in Task 3 and Task 6.
- **Idempotent repeats writing rows.** `addManager` twice, `setFinanceAccess` repeated, the groups webhook with `unchanged` state: one row, not two. Tests per module task.
- **Deep cursor pages and the non-finance partial index.** A cursor deep in the range must still be an index range scan for both viewers. Task 13.
- **Slovak grammar without gendered verbs.** Action texts are verbal nouns („Úprava úlohy“), never „upravil(a)“. Reviewed in Task 14.
